# ML4DC-MuonPOG

A small per-lumisection anomaly study using the 10 one-dimensional `Muons/` monitoring elements in the DIALS `muo` workspace. The experiment uses 2025 `Muon0` PromptReco runs.

## Run

```bash
uv sync
bash runs/01_example.sh      # fetch one ME/run and plot the raw histograms
bash runs/02_all_2025.sh     # collect 2025 Muon0 data; resumable, but lengthy
bash runs/03_ae_base.sh      # train ae_base and plot LS scores
bash runs/04_ae_bin.sh       # train ae_bin and plot scores plus ME reconstructions
```

The first DIALS query requests CERN authentication when needed. Run collection before the experiment on a fresh clone. The collector keeps all 2025 Muon0 processing versions except non-PromptReco 2025G tests; the experiment selects PromptReco only.

## Data and experiment

`data/run_labels.csv`, converted from the curated 2025 run note, is the **tracked input**: one row per PromptReco run (`run_number,label`). Its 744 runs comprise 727 provisional `good`, 8 `bad_well_known`, and 9 `bad_ambiguous`. The experiment checks that these runs match the DIALS-generated `data/runs.csv` before fitting. Labels describe whole runs, not individual LS.

`data/runs.csv` and `data/raw/` are generated by collection and ignored by Git. Each raw Parquet contains one dataset, run, and ME across its available LS. The 727 Good runs are split by run within each era: about 70% train, 15% validation, and 15% test. Both Bad groups join the test set. Only Good training LS fit the scaler and autoencoder; the fixed LS threshold is the **95th percentile** of Good validation LS scores.

`ae_base` uses two summaries from each ME (`log1p(entries)` and mean histogram position), giving 20 inputs to a 20→8→3→8→20 autoencoder. Its model, LS scores, metrics, and plots live in `result/ae_base/`.

`ae_bin` takes all 1,080 stored bins from the same 10 MEs. It fits on 20,000 sampled Good training LS, checks 5,000 Good validation LS, then scores every available LS. It reads `ae_base/scores.parquet` for the shared run split. For each ME, its mean bin reconstruction error is divided by that ME's 95th-percentile error on Good validation LS; the score averages the 10 ratios. Since low-count histograms naturally have different errors, this score is further divided by the Good-validation 95th percentile within five `eta_entries` ranges (0, 1–100, 101–1,000, 1,001–5,000, >5,000). The final threshold is **1 for every LS**. `result/ae_bin/plots/` has the same era/all/test, score-distribution, and loss figures as `ae_base`. For one Good, well-known Bad, and ambiguous Bad test run, `result/ae_bin/plots.md` links each ME's **separate** original, predicted, and original-minus-predicted bin-count figures.

The ME calibration prevents the 500-bin global-muon pT histogram from dominating solely because it has more bins. The occupancy calibration reduces false alarms in low-count Good LS, but can suppress anomalies that only change the event count. Run labels are provisional and Good LS statistics vary across eras, so the flagged-LS fractions in `result/ae_bin/metrics.json` are exploratory, not certification performance.

Each model directory keeps its own `model.pkl`, `scores.parquet`, and `metrics.json`. Run labels describe whole runs, not individual LS, so flagged-LS fractions are descriptive rather than LS classification metrics.

## Files

| Path | Purpose |
|---|---|
| `data/run_labels.csv` | Tracked 2025 PromptReco run cohort and study labels. |
| `scripts/fetch.py`, `scripts/collect.py`, `scripts/plot.py` | DIALS retrieval and raw-data diagnostics. |
| `scripts/ae_base.py` | Feature summaries, run split, autoencoder, and LS plots. |
| `scripts/ae_bin.py` | Bin-input AE and original/predicted/residual ME plots. |
| `runs/` | Four short bash recipes. |
| `data/runs.csv`, `data/raw/`, `plots/`, `result/` | Generated contents ignored by Git; output directories retain `.gitkeep`. |
